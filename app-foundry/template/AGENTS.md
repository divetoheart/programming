# App Foundry Agent Rules

This app was generated by App Foundry. Preserve the boring infrastructure so product work stays fast.

## Product-first rules

1. Build the smallest delightful version of the product before adding infrastructure.
2. Use AsyncStorage/local state by default.
3. Do not add Supabase, Firebase, a custom API, authentication, queues, workers, or a database unless the requested feature actually requires shared/server-side data.
4. Do not add Fastlane, custom signing scripts, alternate build services, or bespoke CI. EAS owns build/sign/submit unless an explicit blocker is documented.
5. Keep all purchase logic behind `src/lib/purchases.ts`. Product screens ask for entitlement state; they do not implement receipt logic.
6. Keep analytics behind `src/lib/analytics.ts`.
7. Never commit `.env` or secrets. RevenueCat mobile SDK keys are public SDK keys, but still configure production values deliberately.

## Before release

Run:

```bash
npm run doctor
npm run typecheck
```

Then update `STORE.md` and `PRIVACY.md` to match the real app.

For iOS release:

```bash
npm run ship:ios
```

## Monetization

Default entitlement name: `pro`.

Prefer one simple monetization model per app at launch: one-time lifetime unlock OR one subscription family. Avoid complex pricing until usage proves it is necessary.

## Sale/transfer readiness

Keep bundle identifiers, third-party services, store copy, product IDs, and operational notes documented in the repository. Avoid dependencies on personal infrastructure that cannot be transferred to a buyer.
